## Outcome

Given a root `DmnSource`, load every location-addressable transitive import once and return an
immutable model-source graph in deterministic order.

## First vertical increment

```text
root DmnSource
    -> parse root imports
    -> resolve one imported source
    -> parse imported model
    -> cache by DmnSourceId
    -> return deterministic loaded source set
```

## In scope

- Location-based imports resolved through `DmnModelResolver`.
- Recursive traversal of imported sources.
- One resolver call and parse per stable `DmnSourceId`.
- Deterministic source ordering independent of map iteration.
- Immutable result containing root identity, sources, and import edges.
- Focused root-only, single-level, transitive, diamond, cycle-edge, and limit tests.

## Non-goals

- Namespace/model-name fallback when `locationURI` is absent.
- Complete missing, ambiguous, duplicate, and cycle diagnostics from P1.4.
- Semantic analysis, Runtime IR lowering, or execution.
- Durable caches shared between compilations.
- Filesystem watching or hot reload.

## Architectural constraints

- Source resolution remains behind the resolver-independent `DmnModelResolver` boundary.
- The loader owns traversal and caching; resolver implementations remain policy adapters.
- Stable `DmnSourceId` values define cache identity.
- Models and import edges are immutable and deterministically ordered.
- Configurable source-count and import-depth limits bound graph loading.
- Compiler orchestration may depend on the XML frontend; lower-level modules do not depend on the
  compiler.

## Affected modules and contracts

| Module or contract | Change |
| --- | --- |
| `dmn-compiler` | Add bounded transitive model loading |
| `DmnModelLoader` | Parse, resolve, cache, and traverse location-addressable imports |
| `DmnModelLoadOptions` | Define source-count and import-depth limits |
| `DmnModelLoadResult` | Return immutable root, loaded models, and import edges |
| `LoadedDmnModel` | Associate immutable source bytes with parsed definitions |
| `DmnImportEdge` | Retain resolved graph relationships and import order |
| `dmn-compiler` POM | Add the XML frontend production dependency |

## Acceptance scenarios

1. A root with no imports returns exactly the root source.
2. A root importing one model resolves and returns both sources.
3. A three-level chain loads root, intermediate, and leaf in stable identity order.
4. A diamond graph resolves and parses the shared leaf exactly once.
5. Reordering resolver registration does not change the result.
6. A resolver returning an already-loaded stable identity reuses the cached source.
7. A cycle stops at the identity cache and preserves its closing edge for later validation.
8. Exceeding configured source-count or import-depth limits fails deterministically.

## Open decisions

Cycle classification was intentionally deferred to P1.4. P1.3 stops recursion through its
identity cache and preserves the edge so the subsequent slice can diagnose the cycle.

## Suggested delivery sequence

1. Define immutable loaded-source and import-edge result contracts.
2. Implement the root-only case.
3. Add one direct import through the in-memory resolver.
4. Add recursive traversal and identity-based caching.
5. Define and test deterministic ordering.
6. Add diamond, cycle-edge, and limit tests.
7. Run `dmn-compiler` tests, then the complete reactor because the compiler contract is public.
8. Mark P1.3 complete only when evidence is linked from the development plan.

## Completion evidence

- Focused loader tests cover every acceptance scenario.
- Resolver counting proves that diamond dependencies load once.
- Reordered resolver registration produces equal results.
- All 21 compiler tests at P1.3 completion passed.
- The complete eight-project Maven reactor passed.
- Compiler module documentation and the P1.3 development-plan evidence entry were updated.
- ADR: [ADR-0011](../../architecture/adr/adr-0011-deterministic-compilation.md); no new ADR was
  required.
- Benchmark/artifact: not applicable.

## Result

Implemented bounded recursive loading through `DmnModelLoader`, stable identity caching, canonical
source aliases, immutable `LoadedDmnModel` and `DmnImportEdge` results, deterministic ordering, and
source-count/import-depth limits. Cycle traversal terminates through the cache while retaining the
closing edge. Namespace/model-name fallback, graph diagnostic classification, semantic processing,
and durable caches remained deferred as specified.
