## Outcome

A complete suite of version-controlled `.dmn` XML test fixtures in `dmn-compiler/src/test/resources/corpus/` exercises multi-file import resolution, reference linking, item definition importing, BKM invocations, cycle detection, namespace collision resolution, diagnostic handling, and end-to-end runtime evaluation through the public `DmnCompiler` and `DmnRuntime` interpreter.

## In scope

- Fixture scenarios P2.1 to P2.9 added as actual `.dmn` XML files.
- Single import, 3-level transitive import, diamond import topologies.
- Cross-model BKM function invocation and ItemDefinition import.
- Disambiguation of identical model names across different target namespaces.
- Diagnostic assertions for missing imports and cross-model dependency cycles.
- End-to-end evaluation of a multi-file business model set (*Lending Eligibility*).
- `DmnMultiFileCorpusTest` verifying all scenarios via both `ClasspathDmnModelResolver` and `FilesystemDmnModelResolver`.

## Non-goals

- Dynamic code generation (Java/gRPC) — deferred to P5/P7.
- External function host bindings (PMML/Java native methods).

## Architectural constraints

- Fixtures must be valid DMN 1.3 / 1.4 XML models readable by `dmn-frontend-xml`.
- Runtime execution must remain completely decoupled from original XML parsed structures.
- Model resolvers must function independently of underlying filesystem paths.
