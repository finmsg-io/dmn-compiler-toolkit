## Outcome

Given a valid `DmnModelLoadResult`, parse FEEL and run the semantic pipeline for every loaded model
against one complete model repository. Return an immutable, source-addressable semantic model set
with deterministic ordering, import edges, per-model compilation order and bindings, and shared
source/model-aware diagnostics.

## In scope

- Add a compiler-side whole-model-set semantic analyzer.
- Parse FEEL for every loaded model before semantic analysis.
- Analyze each model with all other parsed models available for cross-model linking.
- Associate each analyzed model, compilation order, and binding set with its `DmnSourceId` and
  `DmnModelIdentity`.
- Preserve resolved import edges from the load result.
- Adapt FEEL and semantic diagnostics to `DmnCompilerDiagnostic`.
- Preserve load diagnostics unchanged.
- Stop before FEEL when source loading contains errors.
- Stop before semantic analysis when any FEEL parse error exists.
- Return deterministic immutable models, edges, and diagnostics.
- Define severity-based validity consistently with P1.5.

## Non-goals

- Expose the final one-call `DmnCompiler` facade; that belongs to P1.7.
- Runtime IR lowering, optimization, code generation, or execution.
- Namespace/model-name fallback for location-less imports.
- Redesign lower-level FEEL or semantic diagnostic contracts.
- Add source ranges or semantic paths to the shared P1.5 diagnostic contract.
- Continue semantic analysis over an incomplete or FEEL-invalid model set.
- Define global Runtime IR compilation order across model boundaries.
- Persist semantic results or introduce durable caches.

## Architectural constraints

- Orchestration belongs to `dmn-compiler`; lower-level modules remain independent of compiler
  result and diagnostic types.
- `dmn-compiler` may depend on `dmn-feel-parser` and `dmn-semantic-analysis` in the established
  dependency direction.
- Inputs and outputs are immutable.
- Model, edge, and diagnostic ordering is explicit and deterministic.
- Stable source identity and DMN model identity remain separate.
- Expected FEEL and semantic failures are result diagnostics, not unchecked exceptions.
- A phase with errors prevents later phases from running over an invalid whole model set.
- Native lower-level diagnostics are adapted at the compiler boundary.

## Acceptance scenarios

1. A valid root-only load result produces exactly one source-addressable semantic model.
2. A valid root and imported model are both analyzed against the same repository and returned in
   stable source-ID order.
3. Cross-model compilation order and bindings remain associated with the model whose pipeline
   produced them.
4. Models and all nested result collections are immutable.
5. Reordered loaded-model input produces an equal result.
6. A load result containing an error preserves its diagnostics and produces no semantic models.
7. A FEEL syntax error is reported with `ERROR`, `FEEL_PARSING`, source/model identity, and a stable
   code; semantic analysis does not run for the set.
8. A semantic failure is reported with `ERROR`, `SEMANTIC_ANALYSIS`, its native stable code, and
   source/model identity.
9. Multiple semantic diagnostics from different models remain distinguishable by source identity
   and are deterministically ordered.
10. A valid result has no error diagnostics, `isValid()` is true, and `hasErrors()` is false.
11. P1.3–P1.5 loader and diagnostic behavior remains unchanged.

## Open decisions

Resolved for implementation:

- the analyzer accepts `DmnModelLoadResult`; P1.7 will compose loading and analysis;
- semantic entries contain no nested diagnostics—the top-level shared list is authoritative;
- load errors stop before FEEL and FEEL errors stop before semantic analysis;
- every model is analyzed as a root against all other parsed models;
- per-model compilation orders are retained rather than inventing a global lowering order;
- FEEL diagnostics use stable code `DMN-FEEL-SYNTAX`; native semantic codes are preserved;
- unavailable path/range fields remain encoded only in messages until the shared contract grows.

## Suggested delivery sequence

1. Add compiler dependencies on FEEL parsing and semantic analysis.
2. Define immutable semantic-model and model-set result contracts.
3. Implement load and FEEL phase gates.
4. Analyze every parsed model against the complete repository.
5. Adapt lower-level diagnostics with source/model identity.
6. Add root-only, linked-model, phase-gate, diagnostic, ordering, and immutability tests.
7. Run compiler tests and the complete Maven reactor.
8. Update canonical documentation and attach completion evidence.

## Result

Implemented `DmnSemanticModel`, `DmnModelSetSemanticResult`, and
`DmnModelSetSemanticAnalyzer`. The analyzer accepts the deterministic loaded graph, preserves load
diagnostics, parses FEEL for every source, gates semantic analysis when FEEL errors exist, and then
analyzes each parsed model against all other parsed models. Results retain source and model
identity, per-model compilation order and bindings, resolved import edges, and one authoritative
shared diagnostic list.

FEEL failures use `DMN-FEEL-SYNTAX` with phase `FEEL_PARSING`; native semantic codes are preserved
with phase `SEMANTIC_ANALYSIS`. All adapted failures use source/model identity and error severity.
Five `DmnModelSetSemanticAnalyzerTest` scenarios and all 37 compiler tests pass. The complete
eight-project Maven reactor, strict MkDocs build, architecture dependency check, and
`git diff --check` pass. No new ADR was required. The one-call compiler facade, Runtime IR
lowering, richer diagnostic locations/paths, and global lowering order remain deferred.
