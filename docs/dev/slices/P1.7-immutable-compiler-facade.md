## Outcome

One supported `DmnCompiler` call accepts a root `DmnSource`, resolver, and immutable options; loads
the bounded transitive graph; parses FEEL; performs whole-model-set semantic analysis; lowers the
valid set to linked Runtime IR; optimizes it; and returns an immutable deterministic compilation
result with authoritative shared diagnostics.

## In scope

- Add the public `DmnCompiler` orchestration facade.
- Add immutable `DmnCompilerOptions` with model-load limits.
- Add immutable `DmnCompilationResult` exposing loaded, semantic, and optional optimized Runtime IR
  stages plus one ordered diagnostic list.
- Provide a single-file convenience overload and resolver-aware overloads.
- Preserve P1.3–P1.6 source resolution, phase gates, identities, diagnostics, and ordering.
- Lower all valid semantic models through `RuntimeIrLowerer.lowerModelSet`.
- Optimize successful Runtime IR through `RuntimeIrOptimizer`.
- Convert expected Runtime IR lowering failures into shared diagnostics.
- Do not lower or optimize when an earlier phase has errors.
- Add end-to-end root-only, transitive, invalid-import, invalid-FEEL, options, and determinism tests.

## Non-goals

- Java or other code generation.
- Runtime execution through the interpreter.
- A CLI, Maven plugin, language server, IDE integration, or service API.
- Namespace/model-name fallback for location-less imports.
- Persistent caches or filesystem watching.
- Warning filtering, diagnostic localization, or source-range expansion.
- Runtime IR persistence or a serialized compilation-result format.

## Architectural constraints

- `dmn-compiler` is the only orchestration layer and may depend on every stage it coordinates.
- Lower-level modules remain independent of compiler facade and result types.
- Inputs, options, intermediate results, and final results are immutable.
- Model and diagnostic ordering remains deterministic.
- Expected compilation failures are returned as diagnostics; invariant violations still fail fast.
- Runtime IR exists only for a compilation without error diagnostics through semantic analysis and
  successful lowering.
- The single-file overload uses the same pipeline and contracts as resolver-backed compilation.

## Acceptance scenarios

1. A valid root-only source compiles through optimization with one call.
2. A root with a transitive location import compiles both models into one linked Runtime IR.
3. Single-file and explicit empty-resolver calls produce equal results.
4. Resolver registration order does not change the result.
5. Load diagnostics stop later phases and leave optimized Runtime IR absent.
6. FEEL or semantic diagnostics stop lowering and leave optimized Runtime IR absent.
7. An expected lowering failure becomes an `ERROR` diagnostic in phase `RUNTIME_IR_LOWERING`.
8. Compiler load limits are passed to the loader unchanged.
9. The root identity is consistent across loaded, semantic, and compilation results.
10. Diagnostics are immutable, authoritative, and deterministically ordered.
11. Successful results report `isSuccess()` true; any error reports `hasErrors()` true.
12. All P1.3–P1.6 tests remain green.

## Open decisions

Resolved for implementation:

- the final result retains loaded and semantic stage results for tooling and evidence;
- the top-level diagnostic list is authoritative and equals the latest accumulated phase list;
- Runtime IR is optional and absent after any error;
- model-set lowering order follows deterministic semantic source order;
- only expected `RuntimeIrLoweringException` is adapted; unexpected defects propagate;
- options initially contain load bounds only and can grow compatibly in later slices;
- single-file compilation uses an empty in-memory resolver.

## Suggested delivery sequence

## Result

Implemented `DmnCompiler`, `DmnCompilerOptions`, and `DmnCompilationResult`. One call now composes
bounded transitive loading, whole-set FEEL parsing and semantic analysis, linked Runtime IR
lowering, and optimization. The immutable result retains the loaded and semantic stage evidence,
an optional optimized Runtime IR model, and one authoritative deterministic diagnostic list.

The convenience overload and explicit empty resolver are equivalent. Load, FEEL, and semantic
errors stop later phases; expected Runtime IR lowering failures become
`DMN-RUNTIME-IR-LOWERING` diagnostics. Six `DmnCompilerTest` scenarios and all 43 compiler tests
pass. The complete eight-project Maven reactor, dependency-direction check, strict MkDocs build,
and `git diff --check` pass. No new ADR was required. Code generation, execution, richer source
locations, and real multi-file corpus expansion remain subsequent work.
