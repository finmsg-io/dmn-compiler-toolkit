## Outcome

`DmnRuntime` and `dmn-feel-parser` provide an expanded FEEL conformance baseline supporting 3-valued boolean logic (`true`, `false`, `null`), null propagation for arithmetic and comparison expressions, all 7 DMN decision table hit policies (`UNIQUE`, `FIRST`, `PRIORITY`, `ANY`, `RULE_ORDER`, `OUTPUT_ORDER`, `COLLECT`), and multi-word FEEL identifier names containing spaces.

## In scope

- FEEL 3-valued logic for `AND`, `OR`, and `NOT` operations.
- Strict null propagation across binary arithmetic operators (`+`, `-`, `*`, `/`, `**`) and comparison operators (`<`, `<=`, `>`, `>=`).
- Null-safe equality (`=`, `!=`) where `null = null` evaluates to `true` and `5 = null` evaluates to `false`.
- Null-safe evaluation result container (`DmnEvaluationResult`).
- All 7 DMN Decision Table hit policies (`UNIQUE`, `FIRST`, `PRIORITY`, `ANY`, `RULE_ORDER`, `OUTPUT_ORDER`, `COLLECT`) and output aggregations (`COUNT`, `SUM`, `MIN`, `MAX`).
- ANTLR FEEL grammar (`FeelParser.g4`) expansion allowing multi-word identifier names (`IDENTIFIER+`) with spaces.

## Non-goals

- Native code generation or bytecode lowering (deferred to P5/P7).
- Custom host Java plugin functions.

## Architectural constraints

- Interpreter execution must be side-effect-free, thread-safe, and deterministic.
- Null propagation must align strictly with OMG DMN 1.5 specification requirements.
- AST builder and parser must remain decoupled from specific runtime execution models.
