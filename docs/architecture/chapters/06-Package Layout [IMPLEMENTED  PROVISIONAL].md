# Chapter 6 --- Package Layout \[IMPLEMENTED / PROVISIONAL\]

## 6.1 Current Package Layout

The package structure currently reflects the two implemented modules.

``` text

│
├── model                         generated by protobuf
│
└── frontend.xml
    ├── XmlCursor

    ├── dmn
    │   ├── DmnNamespaces

    │   ├── DmnXmlContext
    │   ├── DmnXmlReader
    │   └── reader
    │       ├── DefinitionsReader
    │       ├── DefinitionsBodyReader

```

## 6.2 Semantic Model Package

All generated protobuf Java classes are placed directly in:

``` text
io.finmsg.dmn.model
```

Examples:

``` text
io.finmsg.dmn.model.Definitions
io.finmsg.dmn.model.Decision
io.finmsg.dmn.model.DecisionTable
io.finmsg.dmn.model.ItemDefinition
io.finmsg.dmn.model.FeelSource
io.finmsg.dmn.model.Expression
```

The current implementation does not use handwritten domain classes under
subpackages such as `model.decision` or `model.type`. The protobuf
schema files provide the logical decomposition while Java generation
uses a single package.

## 6.3 XML Frontend Package

The active root is:

``` text
io.finmsg.dmn.frontend.xml
```

This supersedes older examples that used `io.finmsg.dmn.xml` or
`io.finmsg.dmn.frontend.reader`.

The structure separates:

-   cursor abstraction
-   VTD-XML implementation
-   DMN version and namespace handling
-   element-specific readers
-   XML exceptions
-   general XML utilities

## 6.4 Reader Design

Readers are small, explicit, stateless components. Each reader receives
an `XmlCursor` positioned on the expected element and returns a built
protobuf message or enriches a supplied builder.

Example flow:

``` text
DmnXmlReader
    |
    v
DefinitionsReader
    |
    v
DefinitionsBodyReader
    |
    +-- ItemDefinitionReader
    +-- InputDataReader
    +-- DecisionReader
    +-- BusinessKnowledgeModelReader
    +-- KnowledgeSourceReader
    +-- DecisionServiceReader
```

Readers use generated protobuf builders only during construction. The
returned model is immutable.

## 6.6 Visibility Rules

Current public entry points:

``` text
io.finmsg.dmn.frontend.xml.dmn.DmnXmlReader
io.finmsg.dmn.model.* generated message types
```

Reader implementations, VTD cursor details, and XML utilities should be
treated as internal implementation even where Java visibility is
currently `public`. Stable API guarantees will be introduced with the
compiler API module.

## 6.7 Package Design Rules

1.  XML-specific code stays below `frontend.xml`.
2.  Generated semantic messages stay below `model`.
3.  `model` never imports frontend classes.
4.  Reader names correspond to DMN semantic concepts.
5.  Generic `util` usage remains limited to XML mechanics.
6.  Future compiler stages must not be added below the frontend package.
