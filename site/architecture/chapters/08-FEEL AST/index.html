    Chapter 8 --- FEEL AST [PROVISIONAL SCHEMA]¶

    8.1 Purpose¶

    The FEEL Abstract Syntax Tree (AST) is the compiler representation of FEEL expressions.

    It transforms FEEL from a text-based language into a structured, analyzable representation.

    The FEEL AST is the bridge between:

    • Semantic Model
    • Semantic Analyzer
    • Optimizer
    • Runtime IR Generator
    • Code Generators

    The compiler never performs semantic analysis on FEEL source text.

    The pipeline is:

    FEEL Source

    |
    v

ANTLR Lexer

    |
    v

ANTLR Parser

    |
    v

FEEL AST

    |
    v

Semantic Analysis

    |
    v

Runtime IR

    8.2 Design Goals¶

    The FEEL AST must provide:

    • complete FEEL language representation
    • compiler-friendly structure
    • immutable nodes
    • source location tracking
    • type information attachment
    • optimization support
    • deterministic transformation
    • independence from ANTLR runtime

    8.4 Design Principle¶

    FEEL text exists only at the frontend boundary¶

    After parsing:

    Forbidden:

    evaluate("speed > 100")

    Allowed:

    evaluate(
    BinaryExpression(
        GREATER_THAN,
        Variable("speed"),
        Literal(100)
    )
);

    8.6 AST Node Design¶

    All AST nodes share a common abstraction.

    Example:

    public sealed interface ExpressionNode
permits
    LiteralNode,
    VariableNode,
    BinaryExpressionNode,
    FunctionCallNode,
    ContextNode {

    SourceLocation location();

}

    Every node contains:

    • node type
    • child expressions
    • source location
    • optional type information

    8.19 AST Visitor Pattern¶

    Compiler passes should not depend on concrete node types.

    Use visitors:

    public interface ExpressionVisitor<R> {

    R visitLiteral(
        LiteralNode node
    );

    R visitBinary(
        BinaryExpressionNode node
    );

}

    Used by:

    • type inference
    • optimization
    • code generation
    • pretty printing

    8.20 Source Location Tracking¶

    Every AST node stores location.

    Example:

    traffic.dmn

line 42

column 15

    Model:

    public record SourceLocation(

    String file,

    int line,

    int column

){}

    Benefits:

    • precise compiler errors
    • debugging
    • IDE integration

    8.21 FEEL Type Information¶

    Types are attached after analysis.

    Example:

    Before:

    speed > 100

    AST:

    BinaryExpression

unknown

    After:

    BinaryExpression

operator:

left:

number

right:

number

result:

    8.22 AST Immutability¶

    AST nodes are immutable.

    Example:

    Good:

    BinaryExpressionNode optimized =
    node.replaceChildren(
        newLeft,
        newRight
    );

    Bad:

    node.setLeft(newLeft);

    Benefits:

    • safe optimization
    • parallel compilation
    • deterministic behavior
