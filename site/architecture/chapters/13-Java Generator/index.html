    Chapter 13 --- Java Generator [FUTURE]¶

    13.1 Purpose¶

    The Java Generator is the first production backend of the DMN Compiler Toolkit.

    Its responsibility is to transform optimized Runtime IR into highly optimized Java source code or JVM executable artifacts.

    The Java Generator consumes only Runtime IR.

    It must never depend on:

    • DMN XML
    • VTD-XML
    • FEEL parser
    • ANTLR
    • Semantic Model

    The architecture:

    ```text id="9f0d2m" Runtime IR

                  |

              v

    +-------------------+
    |  Java Generator   |
    +-------------------+

              |

    +---------+----------+

    |                    |

    v                    v

    Java Source Bytecode

        |                    |

    v                    v

    javac / JVM JVM Runtime

    ---

# 13.2 Design Goals

The Java backend should provide:

* maximum JVM performance
* zero reflection
* static typing where possible
* small generated artifacts
* easy debugging
* normal Java integration
* native-image compatibility
* predictable execution

    13.11 Generated Code Optimization¶

    The generator should produce JVM-friendly code.

    Avoid Boxing¶

    Bad:

    Integer speed;

    Good:

    int speed;

    Avoid Reflection¶

    Forbidden:

    field.get(object)

    Preferred:

    input.speed()

    Avoid Generic Dispatch¶

    Bad:

    evaluate(Expression e)

    Good:

    evaluateDecision()

    13.12 Decision Graph Generation¶

    Runtime graph:

    A

|

B

|

C

    Generated Java:

    public Result evaluate(){

    AResult a =
        evaluateA();

    BResult b =
        evaluateB(a);

    return evaluateC(b);

}

    Built-in FEEL functions are mapped.

    Example:

    substring(name,1,3)

    Runtime IR:

    Generated:

    name.substring(1,4)

    13.20 JVM Optimization Strategy¶

    Generated code should enable:

    Method Inlining¶

    Small decision methods:

    private int calculateAge()

    can be inlined by JVM.

    Escape Analysis¶

    Avoid:

    new TemporaryObject()

    Branch Prediction¶

    Generate:

    if(condition)

    rather than:

    switch(expression tree)

    where possible.

    Vectorization¶

    For batch execution:

    Decision[]

↓

SIMD-friendly processing

    13.23 Summary¶

    The Java Generator transforms optimized Runtime IR into production-quality Java.

    It provides:

    • zero XML dependency
    • zero FEEL dependency
    • zero reflection
    • JVM optimized execution
    • normal Java APIs
    • future bytecode support
